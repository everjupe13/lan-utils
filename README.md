# Рядом

Небольшой набор инструментов для localhost и устройств в одной локальной сети. React + TypeScript + Vite, Express, обычный WebSocket через `ws` и собственный JSON-протокол. Socket.IO не используется.

## Запуск

Нужен Node.js **22.12+** (рекомендуется Node.js 24 LTS) и npm.

```sh
npm install
npm run dev
```

Откройте **http://localhost:5173**:

- `/` — минимальное меню инструментов и адреса для подключения других устройств.
- `/chat` — комнаты, личные диалоги, сообщения и передача ссылок.
- `/gambit` — шахматы для двух игроков.

На другом устройстве в той же сети Wi-Fi или LAN откройте адрес из блока «Подключить другое устройство», например `http://192.168.1.20:5173/chat`. Устройство появится в списке после открытия страницы чата и ввода имени. Автоматического сканирования всей сети нет.

Vite и сервер по умолчанию принимают подключения на `0.0.0.0`. В разработке используйте порт **5173**: Vite проксирует `/ws`, `/ws/chat` и `/api` на бэкенд. Если включён брандмауэр, разрешите входящие подключения к порту 5173.

## Чаты и передача ссылок

При первом входе задайте имя устройства. Предлагается редактируемая подсказка на основе браузера и ОС; это не системное имя компьютера. Для работы через обычный HTTP не требуются Client Hints, HTTPS, установка приложения или расширения.

Каждое подключившееся устройство попадает в комнату «Общая». Можно создать другую комнату, открыть существующую или выбрать устройство для личного диалога. Комнаты публичные для посетителей этого сервера. Личный диалог виден только двум участвующим устройствам; сервер проверяет участников при чтении и отправке.

Вставьте ссылку в сообщение: HTTP(S)-адреса становятся кликабельными. Кнопка «Копировать» копирует текст сообщения; при недоступности Clipboard API используется резервный способ для HTTP. Если браузер запрещает оба способа, текст и адреса можно выделить вручную. «Пригласить» копирует ссылку на текущую комнату с LAN-адресом сервера, в том числе при открытии приложения через localhost.

Сообщения, комнаты, диалоги и серверные сессии хранятся **только в памяти процесса**. Перезапуск бэкенда удаляет их. Сохраняются последние **500 сообщений** в каждом чате; сообщение — до **4000 символов**, имя устройства и название комнаты — до **40**. Лимит — 100 комнат и диалогов суммарно и 256 идентичностей устройств за время работы сервера.

Имя и случайный токен устройства сохраняются в `localStorage`, выбор чата — в `sessionStorage`. История сообщений в браузерное хранилище не записывается. Несколько вкладок одного браузера используют одну идентичность и считаются одним устройством. Устройство исчезает из списка онлайн после закрытия последней вкладки чата; при аварийном обрыве соединения — после heartbeat. После обновления страницы или восстановления связи история снова приходит с сервера.

Клиент ждёт подтверждения отправки, прежде чем очистить введённый текст. При переподключении неподтверждённое сообщение повторяется с прежним идентификатором; сервер отбрасывает дубликаты среди сохранённых сообщений. После перезапуска сервера клиент получает новое состояние и сообщает об очистке истории. Черновики текущей страницы сохраняются при переключении комнат, но не при перезагрузке страницы.

Авторизации пока нет: имя задаёт пользователь, а идентичность восстанавливается по токену браузера. Приложение рассчитано на доверенную локальную сеть. Разные браузеры и профили браузера считаются разными устройствами.

## Гамбит

Откройте `/gambit` в двух отдельных вкладках или браузерах. Укажите разные логины и имена. Создатель комнаты играет белыми, второй игрок входит по коду, ссылке приглашения или из списка и играет чёрными. Партия начинается автоматически после входа второго игрока.

Ход: нажмите на фигуру, затем на подсвеченную клетку. Есть поворот доски под игрока, выбор фигуры при превращении пешки, история ходов, шах, мат, ничья, сдача и выход с поражением из начатой партии. При отключении соперника ходы приостанавливаются; обновление страницы восстанавливает место. Место сохраняется 30 минут после отключения.

Для второго игрока открывайте новую вкладку самостоятельно: команда «Дублировать вкладку» может скопировать шахматную сессию. Шахматная сессия отделена от идентичности устройства в чате.

Правила проверяет [chess.js](https://github.com/jhlywa/chess.js). Сервер — источник истины: проверяет комнату, цвет, очередь, версию позиции и допустимость хода. Ничья автоматически определяется библиотекой, включая троекратное повторение и правило 50 ходов. ИИ, таймер, зрители и база данных пока не реализованы.

## Структура

```text
frontend/src/
  App.tsx                   — маршруты /, /chat, /gambit
  components/ui/            — Button, Card, Input и другие примитивы
  components/home/          — меню инструментов
  components/chat/          — имя устройства, список чатов, сообщения, поле отправки
  components/network/       — адреса для подключения по LAN
  components/chess/         — ChessPage, доска, игроки, история, результат
  components/room/           — шахматные комнаты и приглашения
  components/person/         — шахматный профиль
  components/layout/         — шапки и подвал
  composables/               — React-хуки форм, игры, чата и соединения
  connections/               — общий ConnectionClient и WebSocketTransport
  services/                  — GameSession, ChatSession, браузерные настройки идентичностей
  types/                     — локальное состояние, формы и интерфейсы клиента
  chess/                     — чистые функции доски
  utils/                     — безопасное выделение ссылок, копирование, подсказка имени
  global.css                 — тема и базовый сброс стилей
backend/src/
  app.ts                     — Express, маршруты SPA и сборка сервисов
  server.ts                  — запуск, Origin и адреса сетевых интерфейсов
  network.ts                 — IPv4-адреса сервера
  services/game-service.ts   — шахматные комнаты, правила и состояние партии
  services/chat-service.ts   — устройства, чаты, история и доставка
  transports/                — WebSocket, heartbeat, ограничения сообщений
  types/                     — внутренние серверные модели
  validation/                — схемы входящих сообщений через Zod
packages/shared/
  src/                       — публичные контракты и чистая файловая политика
  dist/                      — собранные ESM-модули и TypeScript-декларации
  test/                      — проверки публичного API пакета
tests/integration/           — совместная проверка клиента и сервера через подменный транспорт
scripts/check-boundaries.mjs — контроль границ пакетов
```

У каждого компонента — CSS Module; глобальный CSS содержит тему и базовый сброс. Общие контракты и чистые проверки принадлежат отдельному npm workspace-пакету `@nearby/shared`. Оба приложения объявляют его production-зависимостью и импортируют только публичные точки входа:

```ts
import type { ChatMessage } from '@nearby/shared/chat';
import type { RoomState } from '@nearby/shared/room';
import { fileNameProblem } from '@nearby/shared/file-policy';
```

Граница зависимостей: `frontend → @nearby/shared ← backend`. Прямые импорты исходников между приложениями и обход публичного API shared запрещены командой `npm run check:boundaries`, включённой в сборку, проверки типов и тесты. В shared нет зависимостей от приложений, Node.js API или DOM; типы файлового хранилища остаются в backend, состояние и интерфейсы UI — во frontend. Совместные тесты, которым действительно нужны оба приложения, расположены в корневой `tests/integration/`.

`packages/shared/package.json` экспортирует только `dist/*.js` и `dist/*.d.ts`. Исходники и внутренние файлы через имя пакета недоступны. Типовые импорты стираются при сборке, runtime-утилиты Vite включает в бандл фронтенда. Бэкенд компилируется через `tsc` и загружает `@nearby/shared` из production-зависимостей; он не обращается к исходникам frontend или shared. Npm связывает локальный workspace по версии `0.1.0`; `tsconfig.paths` и специальные source-алиасы не используются.

`GameSession` и `ChatSession` не зависят от WebSocket или React: они работают через интерфейс `MessageConnection`. Общий `ConnectionClient` управляет подписками и переподключением и получает фабрику `MessageTransport`. Только `WebSocketTransport` обращается к браузерному API WebSocket.

Базовый `useConnection(factory)` возвращает состояние, `connect`, `disconnect`, `send`, `subscribe`. `useWebSocketConnection(options)` создаёт WebSocket-адаптер и использует этот же хук; также экспортирован алиас `useWebSockerConnetion`. Точки выбора транспорта — `useApplication.ts` для шахмат и `useChat.ts` для чатов. Для long polling можно подставить другой `MessageTransport`, сохранив компоненты и сервисы; HTTP-endpoints long polling пока не реализованы.

WebSocket шахмат доступен по `/ws`, чатов — по `/ws/chat`. Контракты находятся в `packages/shared/src/protocol.ts` и `packages/shared/src/chat.ts`, серверные схемы — в `backend/src/validation/`. `/api/network` возвращает адреса этого компьютера, `/api/health` — состояние HTTP-сервера. В собранном приложении Express отдаёт HTML также по прямым ссылкам `/chat` и `/gambit`.

## Команды и настройки

```sh
npm run check:boundaries # границы workspace-пакетов
npm run verify:deployment # проверить готовые dist в отдельном production-окружении без src
npm run build:shared     # отдельная сборка общих контрактов и утилит
npm run typecheck        # shared и TypeScript обоих приложений
npm run test:unit        # shared, приложения и совместные тесты без сетевого порта
npm run test:contracts   # совместные тесты клиента и сервера без сетевого порта
npm run test:integration # настоящий HTTP + WebSocket, включая прямые ссылки SPA
npm test                # все проверки, включая сетевые
npm run format:check    # форматирование
npm run build           # shared → frontend → backend
npm run clean           # удалить только каталоги dist
npm start               # сборка на http://localhost:3001 и http://<LAN-IP>:3001
```

В тестах есть подменный транспорт, который проводит шахматные партии и обмен сообщениями через настоящие сервисы без сети. HTTP-загрузка файлов также проверяется через потоки внутри процесса. Для отдельных сетевых тестов окружение должно разрешать открытие временного localhost-порта.

### Порядок сборки и production

После `npm install` корневая команда `npm run dev` сначала собирает shared, затем запускает его TypeScript watch вместе с Vite и бэкендом. Изменения общих runtime-правил пересобираются автоматически; Vite работает с linked-пакетом без предварительной упаковки в кеш зависимостей. Корневые команды тестов и проверки типов также сначала собирают shared. При запуске отдельного workspace на чистом checkout предварительно выполните `npm run build:shared`.

Для production нужны `frontend/dist`, `backend/dist`, `packages/shared/dist`, манифесты всех workspace-пакетов, корневые `package.json` и `package-lock.json`. После `npm ci --omit=dev` и `npm start` исходники приложений и shared не требуются. Сохраняйте структуру каталогов: Express намеренно раздаёт соседний `frontend/dist`, а npm workspace-ссылка `node_modules/@nearby/shared` ведёт на собранный `packages/shared`.

Shared также можно упаковать отдельно: `npm pack -w @nearby/shared --ignore-scripts`. Архив содержит готовые модули и декларации; для отдельного развёртывания backend этот архив должен быть установлен как обычная production-зависимость. Один `backend/dist` не является автономным бандлом — ему нужны установленные npm-зависимости, включая shared.

После сборки `npm run verify:deployment` копирует только манифесты и `dist` во временный каталог, выполняет `npm ci --omit=dev --ignore-scripts` и проверяет разрешение shared, загрузку собранного бэкенда и клиентский бандл без исходников. Сетевой порт не открывается. Для локального npm-кеша доступен флаг `--offline`: `npm run verify:deployment -- --offline`.

Настройки бэкенда: `HOST` (по умолчанию `0.0.0.0`), `PORT` (3001), `FRONTEND_ORIGINS` (список Origin через запятую). Чтобы ограничить доступ этим компьютером, задайте `HOST=127.0.0.1`. По умолчанию разрешены Origin от `localhost`, `127.0.0.1` и IPv4-адресов этого компьютера на портах 5173 и бэкенда. После смены IP перезапустите сервер. Для собственного DNS-имени задайте `FRONTEND_ORIGINS` явно. `.env` автоматически не загружается.

Vite использует порт 5173 и прекращает запуск, если он занят. При изменении порта бэкенда обновите proxy в `frontend/vite.config.ts`; адрес `127.0.0.1` в proxy относится к серверу и не требует замены для LAN. При запуске собранного приложения откройте порт 3001 в брандмауэре вместо 5173.

## Файлы и скриншоты

В `/chat` нажмите «Прикрепить файл», перетащите файлы в поле отправки или вставьте скриншот из буфера обмена. Файлы сначала попадают в очередь; кнопка «Отправить» запускает передачу. Можно приложить до 10 файлов в очереди, увидеть прогресс, отменить загрузку или повторить неудачную передачу. Текст и файлы отправляются отдельными сообщениями. При выборе другой комнаты очередь остаётся привязанной к исходному чату.

По умолчанию:

- **25 МБ на один файл** — подходит для скриншотов, документов и небольших архивов.
- **500 МБ суммарно на экземпляр сервера**, с учётом записываемых файлов и параллельных загрузок.
- Одновременно записывается один файл от одного устройства; клиент отправляет очередь последовательно.

Объём можно настроить переменными `UPLOAD_MAX_MB` и `UPLOAD_TOTAL_MB`. Например:

```sh
UPLOAD_MAX_MB=50 UPLOAD_TOTAL_MB=1024 npm run dev
```

Числа задаются в МБ (1 МБ = 1024 × 1024 байта); общий лимит должен быть не меньше лимита одного файла. Допускаются целые значения от 1 до 10240. При заполнении хранилища новые загрузки отклоняются с понятной ошибкой, уже отправленные файлы сохраняются. Очистить всё хранилище можно перезапуском сервера.

Бинарные данные записываются потоком **на диск**, в приватную служебную папку `backend/.runtime/files/run-<pid>-<uuid>/`. В памяти остаются только метаданные. Исходное имя хранится отдельно; имя на диске генерирует сервер. Папка исключена из Git и не раздаётся как статические файлы. Рекомендуется временное дисковое хранение, а не RAM или base64 в сообщениях: крупные вложения не раздувают историю чата и потребление памяти сервера.

Очистка выполняется:

1. При штатной остановке (`Ctrl+C`, `SIGTERM`) — отменяются активные записи и удаляется папка текущего экземпляра.
2. При следующем запуске — удаляются оставшиеся папки процессов, которые уже не работают. Папки других работающих экземпляров сохраняются.
3. При выходе сообщения за пределы истории последних 500 сообщений — удаляется его вложение.
4. При ошибке, превышении лимита или отмене передачи — удаляется недописанный файл и освобождается квота.

При `SIGKILL`, аварии питания или завершении всей системы выполнить код очистки в этот момент невозможно: файлы будут удалены на следующем запуске. После перезапуска старые ссылки на вложения недействительны. Скачанные копии на устройствах получателей сервер, разумеется, не удаляет.

Файлы отправляются через HTTP `POST /api/chat/files`, скачиваются через `GET /api/chat/files/:id`; WebSocket передаёт метаданные сообщения. Оба запроса требуют токен устройства в заголовке `Authorization: Bearer …`, сервер проверяет участие в соответствующем чате. Токены не помещаются в URL изображений. Лимиты клиент узнаёт по `/api/chat/files/policy`.

Загрузка ограничена белым списком расширений, который проверяет сервер. Допустимые категории:

| Категория      | Расширения                                                             |
| -------------- | ---------------------------------------------------------------------- |
| Изображения    | png, jpg, jpeg, jfif, gif, webp, bmp, tif, tiff, avif, heic, heif, ico |
| Видео          | mp4, m4v, mov, webm, mkv, avi, mpg, mpeg, 3gp, ogv, mts, m2ts          |
| Аудио          | mp3, wav, ogg, oga, m4a, aac, flac, opus, aif, aiff, wma, amr          |
| Документы      | pdf, docx, xlsx, pptx, odt, ods, odp, rtf                              |
| Текст и данные | txt, md, markdown, json, csv, tsv, log                                 |
| Архивы         | zip, 7z, rar, tar, gz, bz2, xz, tgz, tbz, tbz2, txz, zst, tzst         |

Составные архивные расширения (`.tar.gz`, `.tar.xz` и другие) разрешены. Регистр не важен. Другие расширения, включая Windows/macOS-программы, установщики, скрипты, ярлыки, SVG и HTML, отклоняются с HTTP 415. Расширения Office с макросами (`.docm`, `.xlsm`, `.pptm` и подобные) и старые бинарные `.doc`, `.xls`, `.ppt` не включены: используйте современные форматы из списка.

Также запрещены подозрительные двойные расширения (`report.exe.pdf`, `installer.app.zip`, `notes.ps1.txt`), управляющие символы, двунаправленные маркеры текста, двоеточие и пробелы по краям имени. При сокращении длинного имени конечное расширение сохраняется. Дополнительно проверяется начало содержимого: MZ/Windows, Mach-O и universal/FAT macOS, ELF и shebang-скрипты отклоняются даже после переименования в допустимое расширение. Недописанный файл удаляется, квота освобождается. Форматы заголовков описаны в [спецификации PE Microsoft](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format) и заголовках [Mach-O](https://github.com/apple-oss-distributions/xnu/blob/main/EXTERNAL_HEADERS/mach-o/loader.h), [FAT Apple](https://github.com/apple-oss-distributions/xnu/blob/main/EXTERNAL_HEADERS/mach-o/fat.h).

Белый список — фильтр типов файлов, а не антивирусная проверка. **Архивы не распаковываются: исполняемые файлы внутри архива не обнаруживаются.** Содержимое документов и вложенные макросы также не анализируются. Это ограничение относится в том числе к зашифрованным архивам.

Предпросмотр предоставляется по запросу только для PNG, JPEG, GIF и WebP, определённых по содержимому. Остальные разрешённые типы скачиваются как вложения. Предпросмотр не загружает автоматически всю историю изображений; временные Blob URL освобождаются при закрытии изображения или удалении компонента.

Единый список и проверка имён находятся в `packages/shared/src/file-policy.ts` и доступны обоим приложениям через `@nearby/shared/file-policy`. `/api/chat/files/policy` публикует список вместе с лимитами. Выбор файлов, перетаскивание и вставка из буфера используют одну проверку; диалог выбора получает атрибут `accept`, а полный список можно открыть под полем отправки. Проверку сигнатур выполняет серверный `backend/src/validation/file-content.ts`.

Реализация: `backend/src/services/file-store.ts`, `backend/src/routes/files.ts`, `frontend/src/services/ChatFiles.ts`, `frontend/src/composables/useFileTransfers.ts`. HTTP-передача отделена от логики чат-соединения и не зависит от выбранного транспорта сообщений.
