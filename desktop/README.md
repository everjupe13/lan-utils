# Рядом для macOS

Нативная SwiftUI-утилита для macOS 13.5 и новее (минимальная версия для вложенного Node.js 24). Окно управления и иконка в строке меню запускают собранный Express-сервер. Чат, шахматы и файлы открываются в обычном браузере; другие устройства подключаются по LAN-адресу.

## Сборка

Нужны установленные зависимости проекта, официальный Node.js 22.12+ (например, через nvm) и Apple Command Line Tools с компилятором Swift. Полная установка Xcode не обязательна.

```sh
npm install
npm run build:mac
```

Результат — `dist/Рядом.app`. Откройте его в Finder; при желании перенесите в «Программы». Приложение содержит Node.js, frontend, backend, shared и production-зависимости. Для запуска не нужны терминал, npm, установленный Node.js или исходный проект. При упаковке зависимости берутся из текущей установки npm без скачивания. Сборка предназначена для архитектуры текущего Node.js: Apple Silicon либо Intel; это не universal binary.

По умолчанию используется локальная ad-hoc подпись. Обновления дополнительно защищены независимой подписью Ed25519. Для обычного распространения другим пользователям через интернет рекомендуется Developer ID и нотариализация Apple: они отвечают за доверие Gatekeeper, тогда как Ed25519 подтверждает подлинность обновлений.

## Обновления приложения

Используется [Sparkle 2](https://sparkle-project.org/documentation/). При ручном запуске проверяется наличие новой совместимой версии. Если она найдена, открывается стандартный диалог с описанием изменений и кнопкой установки. Проверка не мешает работе сервера; без интернета приложение продолжает работать. Открывать пустой диалог при каждом запуске не требуется.

В окне управления, меню возле часов и меню приложения доступны «Проверить обновления…» и «Обновить до …», когда версия найдена. Проверку при запуске можно отключить; ручная проверка остаётся доступной. Sparkle также проверяет обновления по своему расписанию, пока приложение работает (по умолчанию раз в сутки). Автоматической установки без согласия пользователя нет.

Перед установкой сервер штатно останавливается. После замены `.app` Sparkle запускает новую версию. Настройки UserDefaults сохраняются; чаты, партии и временные вложения очищаются при остановке сервера. Приложение по-прежнему не запускается при входе в macOS.

**Версию 0.1.0 нужно один раз заменить вручную:** в ней ещё нет механизма обновлений. Установите `Рядом.app` версии 0.2.0 в «Программы», затем следующие опубликованные версии можно устанавливать из приложения.

### Настройка репозитория один раз

`desktop/release.json` содержит версию, номер сборки, GitHub-репозиторий, публичный ключ подписи обновлений и фиксированную версию/SHA-256 Sparkle. Этот файл нужно хранить в Git.

- `publicKey` — открытый Ed25519-ключ для проверки подписи. Он не позволяет подписывать обновления и безопасен в публичном репозитории.
- `sparkle.sha256` — контрольная сумма официального архива библиотеки Sparkle; проверяется при её скачивании для сборки. Это не секрет.
- **Закрытый ключ** хранится в `.private/sparkle-private-key`. `.private/` исключена из Git, приложение и архивы релиза её не содержат. Только закрытый ключ позволяет подписать новое обновление. Не заменяйте его для каждой версии.

Для этого проекта ключ уже создан локально. Сохраните резервную копию файла `.private/sparkle-private-key`. В GitHub откройте **Settings → Secrets and variables → Actions → New repository secret**, задайте имя `SPARKLE_PRIVATE_KEY` и вставьте содержимое этого файла. Не используйте Repository Variables для закрытого ключа. На другой машине восстановите этот же ключ из резервной копии; без него GitHub-сборки работают только при наличии соответствующего Secret.

Для нового проекта без ключей используется `npm run setup:mac-updates`. Скрипт не перезапишет закреплённый публичный ключ другим и не выводит закрытый ключ в терминал. После первоначальной настройки закоммитьте `desktop/release.json` и `.gitignore`, но не `.private/`.

Репозиторий и Releases должны быть публично доступны для текущей схемы. Клиент не содержит GitHub-токен. Если репозиторий станет приватным, перенесите канал и архивы на доступный HTTPS-хостинг: не встраивайте персональный токен в приложение.

### Выпуск новой версии через GitHub Actions

1. В `desktop/release.json` измените `version`, например на `0.2.1`, и **увеличьте `build`**, например с `2` до `3`. Именно `build` Sparkle сравнивает при поиске обновлений; он должен увеличиваться для каждого релиза. Публичный ключ оставьте прежним.
2. Обновите `desktop/RELEASE_NOTES.md` описанием изменений этой версии.
3. Закоммитьте изменения и отправьте их в репозиторий.
4. Создайте и отправьте тег, точно совпадающий с версией:

   ```sh
   git tag v0.2.1
   git push origin v0.2.1
   ```

5. Workflow `.github/workflows/release-macos.yml` соберёт Apple Silicon и Intel версии на отдельных macOS runners, проверит сервер, подпишет архивы и каналы обновлений и создаст **черновик GitHub Release** с четырьмя файлами:
   - `Nearby-0.2.1-arm64.zip`, `appcast-arm64.xml`;
   - `Nearby-0.2.1-x64.zip`, `appcast-x64.xml`.
6. Проверьте черновик и опубликуйте его через **Publish release**, выбрав **Set as the latest release**. После публикации новая версия станет доступна приложениям. Draft и prerelease не предназначены для стабильного канала `latest`.

Каждое изменение исходников не требует релиза. Создавайте релиз, когда хотите доставить пользователям очередную версию. Не заменяйте файлы уже опубликованного релиза: выпускайте новую версию и тег. Workflow не перезаписывает опубликованные релизы. Не изменяйте подписанные XML-файлы вручную: подпись перестанет совпадать.

Канал Apple Silicon: `https://github.com/everjupe13/lan-utils/releases/latest/download/appcast-arm64.xml`. Intel использует `appcast-x64.xml`. В каждый стабильный релиз включайте оба канала и обе сборки. До первой публикации релиза приложение сообщит о невозможности проверки; наличие коммитов в `main` не создаёт обновление.

### Локальная подготовка релиза

```sh
npm run release:mac
```

Команда создаёт `.app` и в `dist/updates/<архитектура>/` — ZIP и подписанный appcast. Публикации в GitHub эта команда не выполняет. Она использует локальный закрытый ключ или `SPARKLE_PRIVATE_KEY` из окружения. Если ключ не соответствует закреплённому публичному ключу, сборка релиза прерывается.

### Developer ID и нотариализация (для распространения)

В GitHub Actions можно дополнительно настроить Secrets:

| Secret                       | Значение                                                                         |
| ---------------------------- | -------------------------------------------------------------------------------- |
| `MACOS_CERTIFICATE_P12`      | Экспортированный Developer ID Application сертификат с закрытым ключом, в base64 |
| `MACOS_CERTIFICATE_PASSWORD` | Пароль этого `.p12`                                                              |
| `MACOS_SIGNING_IDENTITY`     | Полное имя `Developer ID Application: … (TEAMID)`                                |
| `APPLE_ID`                   | Apple ID для нотариализации                                                      |
| `APPLE_TEAM_ID`              | Team ID                                                                          |
| `APPLE_APP_PASSWORD`         | App-specific password для notarytool                                             |

Workflow импортирует сертификат во временную связку ключей, подписывает Node.js, Sparkle с помощниками и `.app`, отправляет приложение на нотариализацию, прикрепляет результат, затем подписывает итоговый архив ключом Sparkle. При отсутствии всех этих Apple Secrets создаётся ad-hoc сборка; GitHub Secret `SPARKLE_PRIVATE_KEY` остаётся обязательным.

Для локальной сборки `MACOS_SIGNING_IDENTITY` задаёт установленный Developer ID сертификат, а `MACOS_NOTARY_PROFILE` — заранее сохранённый профиль `notarytool`. Эти данные не записываются в исходный код. Сертификат Apple и ключ Sparkle — разные ключи с разными задачами.

## Использование

- Ручной запуск `.app` открывает окно и включает сервер.
- **On/Off** включает и останавливает сервер, оставляя утилиту открытой.
- **Открыть Рядом в браузере** открывает локальный интерфейс.
- LAN-адрес можно скопировать и открыть на другом устройстве в той же сети.
- Чтобы поменять порт, доступ из LAN или лимиты файлов, выключите сервер, измените настройки и включите его снова.
- Закрытие окна оставляет приложение в строке меню. Окно возвращается через «Управление и настройки…».
- **Выйти** завершает сервер и утилиту. При аварийном закрытии утилиты сервер также прекращает работу благодаря закрытию родительского stdin pipe.

Приложение не регистрирует Login Item, LaunchAgent или LaunchDaemon и не запускается при входе в систему. Сервер запускается только вместе с ручным открытием утилиты либо переключателем On.

Настройки хранятся в UserDefaults (`local.nearby.desktop`). Вложения и журналы находятся в `~/Library/Application Support/Рядом/`, вне `.app`. На каждый запуск создаётся новый журнал; сохраняется журнал предыдущего запуска. Остановка удаляет временные вложения, историю чата и шахматные партии. Как и веб-версия, приложение рассчитано на доверенную локальную сеть. Если macOS спросит о доступе к локальной сети или входящих подключениях, разрешите его для подключения других устройств.

## Проверка

```sh
npm run build
npm run test:desktop
```

Интеграционные проверки запускают настоящий собранный сервер: раздача интерфейса, лимиты файлов, SIGTERM, потеря родительского pipe, освобождение порта, очистка файлов и ошибка занятого порта. Во время `build:mac` также компилируется SwiftUI, проверяется подпись `.app` и эти же тесты повторяются со вложенным Node.js и упакованными зависимостями.
